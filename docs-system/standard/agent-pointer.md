# Правила для нейросети и проверка видимости

## Блок «Правила для нейросети» (кладётся в `docs/_rules.md`)

```
## Правила для нейросети
1. Ищешь документ: открой docs/_index.md, выбери по строке (id, type, status, quality, суть), затем читай шапку и TL;DR файла (первые ~15 строк). Целиком открывай только нужное.
2. Создаёшь документ: возьми шаблон по типу, заполни шапку (id, title, type, summary, status: draft, quality: unrated, tags, updated), добавь минимум одну ссылку [[id]] и строку в индекс.
3. Меняешь документ: обнови updated и status, при смене сути обнови summary и индекс.
4. Не удаляй документы. Устаревшее переведи в archived и перенеси в docs/archive/.
5. Новый тег сначала добавь в словарь тегов этого файла.
6. Статусы и качество определены в стандарте плагина docs-system (frontmatter.md); не придумывай свои.
```

## Указатель для файлов правил нейросетей

Копировать правила нельзя: копии разойдутся. В файл правил (`AGENTS.md`, `CLAUDE.md`, `GEMINI.md` и т. п.) добавляется только короткий указатель:

```
## Документация
Перед работой с документацией прочитай docs/_rules.md и ищи документы через docs/_index.md.
```

Ставь указатель в тот файл, который читает конкретная нейросеть:

| Нейросеть | Файл |
|---|---|
| Claude Code | `CLAUDE.md` (может содержать `@AGENTS.md`) |
| Codex и большинство агентов | `AGENTS.md` |
| Gemini CLI / Antigravity | `GEMINI.md` |
| Cursor | `.cursor/rules/*.mdc` или `AGENTS.md` |

Если проект использует несколько нейросетей, источником правил делают `AGENTS.md`, а остальные файлы ссылаются на него.

Файл правил держи коротким: только то, чего нельзя вывести из кода.

## Проверка видимости (скилл `verify`)

Цель: понять, находит ли нейросеть правила сама, или нужен указатель.

1. **Подготовь проверочный запрос**, на который можно ответить только по правилам системы. Пример: «Найди в проекте документ о <реальная тема из индекса> и назови его статус и качество. Затем скажи, куда положить новую идею».
2. **Критерий успеха:** нейросеть без подсказок открыла `docs/_index.md` или `docs/_rules.md`, назвала верный `id`/статус и указала `docs/ideas/`.
3. **Запуск.**
   - Claude Code: запусти чистого субагента (без контекста сессии) с этим запросом. Оцени по критерию.
   - Другие нейросети: выдай пользователю готовый запрос и критерий, прогнать должен он.
4. **Решение.** Провал значит добавить указатель в файл правил этой нейросети, затем повторить тест. Успех без указателя значит указатель не нужен, но его всё равно можно оставить.
5. **Итог** записывается в `docs/_audit/verify-<дата>.md` (по шаблону note), включая использованный запрос.
