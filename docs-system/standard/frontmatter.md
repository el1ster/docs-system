# Шапка документа

Каждый файл системы начинается с YAML-шапки. Нейросеть читает шапку и TL;DR, а остальное только если нужно.

```yaml
---
id: arch-overview            # постоянный, уникальный, не меняется при переименовании
title: Обзор архитектуры
type: architecture           # см. список типов в standard.md
summary: Из каких частей состоит система и как они связаны.   # до 200 символов
status: active               # жизненный цикл
quality: adequate            # качество
tags: [architecture, core]
links: [vision, adr-0003-storage]   # id связанных файлов
updated: 2026-10-27
review_by: 2027-01-27        # необязательно
---
```

Обязательные поля: `id`, `title`, `type`, `summary`, `status`, `quality`, `tags`, `updated`. Остальные по необходимости. Для `adr` добавляется `supersedes` / `superseded_by`.

## status (жизненный цикл)

| Значение | Смысл |
|---|---|
| `draft` | Черновик, содержание не подтверждено |
| `active` | Актуален, в работе или в использовании |
| `done` | Выполнен (план, идея реализована). Хранится как история |
| `stable` | Утверждён, меняется редко |
| `stale` | Возможно устарел, нужна проверка |
| `superseded` | Заменён другим документом (указать в `superseded_by`) |
| `archived` | В `docs/archive/`, только история |

Допустимые переходы: `draft → active → stable → stale → active|superseded|archived`. Планы и идеи заканчивают в `done`. Прыжки в `archived` из любого статуса разрешены.

## quality (качество)

| Значение | Смысл |
|---|---|
| `unrated` | Не оценивался |
| `strong` | Полный, точный, по шаблону, можно использовать как образец |
| `adequate` | Годится к использованию, есть мелкие пробелы |
| `weak` | Есть, но неполный, неточный или нарушает шаблон: в очередь на доработку |
| `rewrite` | Проще переписать, чем чинить |

Критерии оценки в `quality-rubric.md`. Оценку ставит аудит или автор, фиксируя в `_audit/` причину для `weak` и `rewrite`.

## tags

- Строчные, латиница, через дефис, 1–5 штук на файл.
- Словарь тегов держится в `docs/_rules.md` (раздел «Теги»): новый тег сначала добавляется туда.
- Обязательно хотя бы один тег области (например `core`, `api`, `ops`) и тип работы по желанию (`idea`, `risk`, `todo`).

## Ссылки

- В тексте: `[[id]]` или `[[id|подпись]]`. Obsidian показывает граф и обратные ссылки.
- В шапке `links`: основные связи, чтобы нейросеть шла по ним, не читая тело.
- Битая ссылка (id не найден) это нарушение, аудит её фиксирует.
