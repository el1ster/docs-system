# Стандарт документации проекта

Единый стандарт, на который опираются все скиллы плагина `docs-system`. Читай только нужные разделы.

Основа: четыре типа Diátaxis (tutorial, how-to, reference, explanation), которые нельзя смешивать в одном файле. Остальное это практики ADR, Keep a Changelog, docs-as-code и файлы правил для нейросетей. Единого формального стандарта не существует, это сводка практик.

## 1. Принципы

1. **Один файл, один тип, одна тема.** Если страница смешивает действие и объяснение, её делят и ссылаются друг на друга.
2. **Шапка и TL;DR первыми.** По первым ~15 строкам нейросеть решает, открывать ли файл целиком. Формат шапки в `frontmatter.md`.
3. **Ссылки вместо копий.** Факт живёт в одном месте, остальные файлы ссылаются через `[[id]]`.
4. **Не дублировать код.** Документ объясняет то, чего нельзя вывести из кода: зачем, как связано, какие ограничения.
5. **Ничего не удалять.** Устаревшее получает статус `archived` и переезжает в `docs/archive/`.
6. **Размер.** Файл до ~300 строк. Длиннее значит делить.
7. **Язык.** Язык проекта (по умолчанию язык владельца), стиль сухой, повелительное наклонение в инструкциях, без воды.

## 2. Обязательный набор

Минимум для любого проекта. В новом проекте создаётся целиком (пустые файлы помечаются `status: draft`, `quality: unrated`). В рабочем проекте аудит находит, чего не хватает.

| Слой | Документ | Тип (`type`) | Путь |
|---|---|---|---|
| Вход | README: что это, быстрый старт, команды, ссылка на `docs/_index.md` | `readme` | `README.md` |
| Вход | Индекс документации | `index` | `docs/_index.md` |
| Вход | Правила системы документации | `rules` | `docs/_rules.md` |
| Идея | Видение: зачем проект, для кого, критерии успеха | `vision` | `docs/overview/vision.md` |
| Идея | Границы: цели, не-цели, анти-цели | `scope` | `docs/overview/scope.md` |
| Идея | Глоссарий терминов проекта | `glossary` | `docs/overview/glossary.md` |
| Структура | Архитектура: части, связи, потоки данных | `architecture` | `docs/architecture/overview.md` |
| Решения | ADR: по одному файлу на решение | `adr` | `docs/decisions/ADR-NNNN-slug.md` |
| Планы | Глобальная дорожная карта | `roadmap` | `docs/plans/roadmap.md` |
| Планы | Точечные планы задач | `plan` | `docs/plans/<slug>.md` |
| Идеи | Идеи и заметки до решения | `idea` | `docs/ideas/<slug>.md` |
| Справка | Референсы: API, конфиги, внешние материалы | `reference` | `docs/reference/<slug>.md` |
| Практика | Инструкции how-to и обучающие tutorial | `howto`, `tutorial` | `docs/guides/<slug>.md` |
| Эксплуатация | Runbook: что делать при сбое | `runbook` | `docs/guides/runbook-<slug>.md` |
| Эксплуатация | Журнал изменений (Keep a Changelog) | `changelog` | `CHANGELOG.md` |
| Участие | Правила работы над проектом | `contributing` | `CONTRIBUTING.md` |
| Для нейросетей | Указатель на `docs/_rules.md` | вне системы | `AGENTS.md` / `CLAUDE.md` / `GEMINI.md` |
| Служебные | Отчёты аудита, планы перестройки, итоги проверок | `note` | `docs/_audit/<имя>-<дата>.md` |

Условные документы (добавлять, если применимо): модель данных (`reference`), политика безопасности (`SECURITY.md`), лицензия, схема развёртывания (`architecture`).

## 3. Раскладка папок

```
README.md  CHANGELOG.md  CONTRIBUTING.md
docs/
  _index.md        индекс (генерируется из шапок)
  _rules.md        инструкция по системе
  _audit/          отчёты аудита и планы перестройки
  overview/        видение, границы, глоссарий
  architecture/
  decisions/       ADR
  plans/           roadmap и точечные планы
  ideas/
  reference/
  guides/          howto, tutorial, runbook
  archive/         устаревшее, не удалять
```

Допустимо подстроить имена под проект, но тогда зафиксировать соответствие в `docs/_rules.md`.

## 4. Стиль

- Заголовок первого уровня один и совпадает с `title`.
- После шапки идёт блок `> TL;DR` (1–3 строки), затем содержание.
- Списки и таблицы лучше сплошного текста. Абзац не длиннее 5 строк.
- Ссылки на файлы проекта только через `[[id]]` (id из шапки), на внешние ресурсы обычные `[текст](url)`.
- Каждая страница, кроме корня, имеет хотя бы одну входящую и одну исходящую ссылку.
- Даты в формате `YYYY-MM-DD`.

## 5. Жизненный цикл и поддержка

- Статус документа меняется вместе с изменением кода, о котором он. Ответственность на том, кто меняет код (человек или нейросеть).
- Индекс `docs/_index.md` обновляется после любого создания, переименования, смены статуса.
- Документ с `status: active`, не обновлявшийся дольше срока из `_rules.md` (по умолчанию 90 дней при активном изменении кода), помечается `stale`.
