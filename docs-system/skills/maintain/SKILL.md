# docs-system:maintain — поддержка системы

Приводит уже созданную систему в порядок после изменений. Небольшие правки метаданных делает сам, содержательные правки только предлагает.

Стандарт в `../../standard/`: `standard.md`, `frontmatter.md`, `quality-rubric.md`.

## Порядок

1. **Проверь, что система есть**: `docs/_rules.md` и `docs/_index.md`. Нет: предложи `init` или `audit`.
2. **Соберись по шапкам** всех файлов `docs/` и корневых документов.
3. **Автоматически исправляй** (метаданные, не смысл):
   - пересобери `docs/_index.md` из шапок;
   - обнови `updated` у файлов, которые менялись, если это очевидно из git;
   - добавь недостающее `links` по явным `[[id]]` в тексте.
4. **Только отмечай и предлагай:**
   - битые `[[id]]` и сироты;
   - `active` без обновлений дольше срока из `_rules.md` при изменившемся коде: предложи `stale`;
   - новые файлы без шапки или не из шаблона;
   - файлы выше 300 строк или со смешанными типами;
   - расхождения с кодом (команды, пути, имена, которых больше нет).
5. **Список слабых документов** (`weak`, `rewrite`, `stale`) выведи по важности, предложи взять верхние в работу.
6. **Итог** кратко: что обновлено автоматически, что требует решения. Подробности пиши в `docs/_audit/maintain-<дата>.md`, только если находок много.

## Границы

- Не переписывай содержательный текст, не переноси и не удаляй файлы: это `plan` и `restructure`.
- Не коммить и не пушь без запроса.
