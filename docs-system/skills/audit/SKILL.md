# docs-system:audit — аудит документации (только чтение)

Читает и оценивает. **Единственное, что можно записать, это отчёт в `docs/_audit/`** (или в место, которое назовёт пользователь). Документы проекта не трогай.

Стандарт в `../../standard/`: `standard.md`, `frontmatter.md`, `quality-rubric.md`. Прочитай все три до начала.

## Порядок

1. **Инвентаризация.** Найди все документы: `*.md`, `*.mdx`, `*.rst`, `*.txt` в корне и `docs/`, README в подпапках, файлы правил нейросетей, вики-папки. Исключи `node_modules`, `.git`, сборочные каталоги и вендорный код.
2. **Структура.** Для каждого файла проверь: есть ли шапка, заполнены ли обязательные поля, один ли тип, размер, входящие/исходящие ссылки, битые ссылки, дубли по смыслу, сироты. Сравни с обязательным набором (`standard.md` §2) и составь список отсутствующих документов.
3. **Качество.** Оцени каждый файл по `quality-rubric.md`. Точность проверяй по коду и фактам проекта (имена, команды, пути, версии). Если проверить нельзя, ставь 1 и отмечай в отчёте.
4. **Статусы.** Предложи `status` по содержанию и свежести (черновик, актуален, возможно устарел). Это предложение, а не запись в файлы.
5. **Для большого корпуса** (больше ~30 файлов) раздели файлы на пачки и раздай субагентам на чтение и оценку. Результаты сведи сам и проверь выборочно.
6. **Отчёт** `docs/_audit/audit-<YYYY-MM-DD>.md` с шапкой по стандарту (`type: note`), включая:
   - сводку: сколько файлов, распределение `quality` и `status`;
   - таблицу по файлам: путь, тип (предложенный), предложенные `status` и `quality`, балл, причина для `weak`/`rewrite`;
   - список отсутствующих документов;
   - структурные нарушения;
   - слабые документы по важности (очередь на доработку).
7. **Предложи следующий шаг:** `docs-system:plan`. Не начинай перестройку сам.

## Границы

- Никаких правок чужих файлов, перемещений и удалений.
- Не выдавай оценку без проверки: «не проверено» честнее выдуманной точности.
