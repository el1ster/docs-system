# docs-system:verify — проверка видимости правил

Выясняет, находит ли нейросеть `docs/_rules.md` и работает ли по индексу, или нужно вписать указатель в её файл правил (`CLAUDE.md`, `AGENTS.md`, `GEMINI.md` и т. д.).

Подробный протокол и таблица файлов по нейросетям в `../../standard/agent-pointer.md`. Прочитай его.

## Порядок

1. **Убедись, что система есть**: `docs/_rules.md`, `docs/_index.md`. Нет: предложи `init`.
2. **Определи, с какими нейросетями работает проект** (спроси или посмотри существующие файлы правил).
3. **Составь проверочный запрос** по реальным данным индекса: найти документ по теме, назвать его статус и качество, сказать, куда положить новую идею. Запиши критерий успеха.
4. **Запуск.**
   - Для Claude Code запусти чистого субагента без контекста сессии и подсказок. Оцени ответ по критерию: открыл ли он индекс или правила сам, верны ли id, статус и путь.
   - Для остальных нейросетей выдай пользователю готовый запрос и критерий. Результат он принесёт сам.
5. **Решение.**
   - Успех: правила видны. Указатель можно не добавлять.
   - Провал: добавь указатель в нужный файл правил этой нейросети (ссылкой, не копией, см. `agent-pointer.md`), повтори тест. Не больше трёх попыток, затем сообщи, что мешает.
6. **Запись.** Результат, запрос и вывод пиши в `docs/_audit/verify-<дата>.md` с шапкой по стандарту.

## Границы

- Файлы правил нейросетей меняй только добавлением указателя, существующее содержимое не трогай.
- Не утверждай, что Gemini или Codex проверены, если их тест не прогнан: так и пиши «не проверено».
