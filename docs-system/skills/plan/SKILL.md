# docs-system:plan — план структурирования и качества

Превращает результаты аудита в **план**. Сами документы не меняет. Пишет только файл плана.

Стандарт в `../../standard/`. Прочитай `standard.md` и `frontmatter.md`.

## Порядок

1. **Найди отчёт аудита** в `docs/_audit/`. Если его нет или он устарел (после него менялись документы), предложи сначала `docs-system:audit` и остановись.
2. **Сначала план структуры**, затем качество. Для каждого документа определи одно действие:
   - `keep` (оставить на месте, только добавить шапку и связи);
   - `move` (перенести в целевую папку; указать откуда и куда);
   - `merge` (слить с другими, указать с какими и что делать с остатками);
   - `split` (разделить смешанные типы или слишком длинный файл);
   - `rewrite` (переписать целиком, для `quality: rewrite`);
   - `improve` (доработать, для `weak`: что именно исправить);
   - `archive` (в `docs/archive/`, статус `archived`);
   - `create` (отсутствующий документ из обязательного набора).
3. **К каждому документу добавь** целевые `id`, `type`, `status` (жизненный цикл) и `quality` (по аудиту, после действия ожидаемое качество указать отдельно).
4. **Раздели на этапы:** (1) шапки, ссылки, индекс, правила, указатели без изменения текста; (2) перемещения, слияния, разделения; (3) переписывание и доработка по приоритету. Каждый этап можно утвердить отдельно.
5. **Запиши план** в `docs/_audit/plan-<YYYY-MM-DD>.md`. Шапка: `type: note`, `status: draft`, плюс поле `approval: pending`. Таблицы с колонками: путь сейчас, действие, путь после, id, type, status, quality сейчас → после, заметка.
6. **Покажи пользователю краткую сводку**: сколько действий каждого вида, что рискованно (слияния, удаления текста), что вне плана. Если пользователь просит, отдай план нейросети на структурирование: она перегруппирует действия, найдёт конфликты и пропуски, но не исполняет.
7. **Дальше только по решению пользователя.** Он ставит `approval: approved` (или говорит об этом в чате, тогда поставь сам) и запускает `docs-system:restructure`.

## Границы

- Пишет только `docs/_audit/plan-*.md`.
- В плане нет «удалить»: устаревшее идёт в архив.
- Не запускай исполнение плана без явного согласия.
