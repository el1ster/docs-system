# docs-system:init — создание системы документации

Создаёт с нуля. Если в проекте уже есть документы, остановись и предложи `docs-system:audit`, а не перезаписывай.

Стандарт лежит в `../../standard/` относительно папки этого скилла (`standard.md`, `frontmatter.md`, `templates.md`, `agent-pointer.md`). Читай нужные файлы перед работой.

## Порядок

1. **Определи состояние проекта.** Пустой, только идея, есть код без документов или есть частичные документы. При частичных документах не создавай поверх: предложи аудит.
2. **Спроси минимум**, если не очевидно: язык документов, нужны ли условные документы, какие нейросети работают с проектом (для указателей).
3. **Собери контекст** для содержательных черновиков: для проекта с кодом прочитай README, манифесты, структуру папок, ключевые модули. Для пустого проекта используй слова пользователя. Не выдумывай факты: неизвестное помечай `TODO: уточнить`.
4. **Создай набор** из `standard.md` §2 по раскладке §3. Каждый файл: шапка по `frontmatter.md` (`status: draft`, `quality: unrated`, `updated` сегодняшняя), TL;DR, тело по шаблону из `templates.md`. Расставь `links` и `[[id]]` между файлами.
5. **Создай `docs/_rules.md`** (шаблон `rules` + блок «Правила для нейросети» из `agent-pointer.md`) и **`docs/_index.md`** из шапок созданных файлов.
6. **Добавь указатель** в файл правил каждой нужной нейросети (`agent-pointer.md`). Если файла нет, создай его с одним указателем. Существующее содержимое не меняй, только дополни.
7. **Проверь целостность:** у каждого файла есть шапка, все `[[id]]` разрешаются, индекс полный.
8. **Отчёт:** что создано (список путей), что заполнено фактами, а что заглушка. Предложи `docs-system:verify`.

## Границы

- Не перезаписывай существующие файлы. При конфликте имён остановись и спроси.
- Не коммить и не пушь без запроса.
