# docs-system:restructure — перестройка по утверждённому плану

Меняет документы. Работает **только по плану** из `docs/_audit/plan-*.md` со статусом `approval: approved` (или с явным согласием пользователя в чате на конкретный этап).

Стандарт в `../../standard/`: `standard.md`, `frontmatter.md`, `templates.md`, `agent-pointer.md`.

## Порядок

1. **Проверь допуск.** Нет плана или нет согласия: остановись и предложи `docs-system:plan`. Согласие даётся на этап; не переходи к следующему сам.
2. **Страховка.** Если это git-репозиторий, проверь чистоту дерева и предложи отдельную ветку и коммит по этапу. Без git сделай копию затрагиваемых файлов в `docs/archive/_backup-<дата>/`.
3. **Исполняй по этапам из плана:**
   - Этап 1: добавь шапки (`status`, `quality` из плана), TL;DR, ссылки `[[id]]`, обнови `_index.md`, `_rules.md`, указатели в файлах нейросетей. Текст не меняй.
   - Этап 2: переносы (в git через `git mv`, чтобы сохранилась история), слияния, разделения. После каждого переноса обнови ссылки и индекс.
   - Этап 3: переписывание и доработка по шаблонам. Сверяй факты с кодом, неизвестное помечай `TODO`.
4. **Большие объёмы.** Раздели действия на независимые пачки (по папкам) и раздай субагентам. Каждой пачке выдай: действие, шаблон, шапку и правило «не выходи за свои файлы». Результаты проверь сам.
5. **Контроль после каждого этапа:** все файлы имеют шапку, все `[[id]]` разрешаются, индекс полный, ничего не удалено (устаревшее в `docs/archive/`). Отметь выполнение в плане (колонка «сделано»).
6. **Закончив**, обнови `quality` по факту (если переписанный документ проверен, поставь оценку, иначе `unrated`), запиши итог в плане и предложи `docs-system:verify`.

## Границы

- Ничего не удаляй. Не меняй действий, которых нет в плане: новое возвращай в `plan`.
- Не коммить и не пушь без запроса.
- Смысл чужого текста не искажай. Сомнение значит пометка `TODO` и вопрос пользователю.
